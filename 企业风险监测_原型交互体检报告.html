一 · 点了完全没反应 10 处 · 演示时会当场卡住

D-01总览页的两个「生成分析」都是摆设已修复总览 › 页头操作区 / 提示条

现象　页头主按钮「生成分析」和黄色提示条里的「生成分析」，点击后 DOM 无任何变化，按钮也不会进 loading 或 disabled。而提示条自己写着「点右上「生成分析」即可」——用户照着做，什么都不会发生。

期望　至少要有三件事之一：跳转到「AI 与邮件」并自动开跑、就地打开确认弹窗、或按钮变「分析中…」并起步进度。

说明　总览页 JS 里只绑定了 .step、柱状 tooltip、企业行和 mCopy，没有和这两个按钮相关的事件。

D-02总览页日期按钮长得像下拉，点不动已修复总览 › 页头右侧

现象　「📅 2026-10-21 星期二」点击零响应，也没有 title 来解释它是只读的。

顺带修正　原页头写「2026-10-21 星期二」，实际是星期三（已按日期算出星期，不再硬编码）。

D-03「近 7 天 / 近 30 天」切换后图表一动不动已修复总览 › 近七日趋势图

现象　两个分段按钮点击后：aria-pressed 仍是 true,false 不变，7 根柱子不变，折线不变。也就是说这个切换器连"选中态"都没给。

D-04同一排三个入口，只有一个能跳已修复总览 › 卡片右上角

D-05风险明细的「数据日期」筛选是死按钮已修复风险明细 › 筛选栏第一个

现象　<button class="fld"> 没有 id、没有监听、点了无变化。它左边有日历图标、和旁边真正能用的「全部栏目」是同一套样式，用户一定会去点。

二 · 有响应，但逻辑没闭环 5 处

这一类不是"没反应"，而是"反应了但不对"——用户会顺着往下走，然后在下一步发现对不上。

D-11全局搜索不会清掉明细页已有的筛选已修复外壳搜索框 → 风险明细

复现　先在风险明细把栏目选成「失信被执行」（当前 4 家），再回顶部搜索框输入「天成」回车。

结果：跳转成功、输入框也填进了"天成"，但栏目筛选仍然停在「失信被执行」，于是显示 0 家。搜索框的 title 写的是"输入企业名后回车，自动跳到风险明细并检索"——用户的预期是"搜到这家企业"，不是"搜不到"。

期望　搜索前先 clearFilters()，或者保留筛选但在结果区显式提示「当前筛选：失信被执行 · 1 个条件」。前者更符合搜索的语义。

D-12批量导入说"已导入 3 家"，名单里一家都没多已修复配置 › 企业名单 › 批量导入

复现　批量导入 → 选文件 → 列映射 → 校验 → 「确认导入 3 家」。

toast 说"已导入 3 家，跳过 2 行"，但底部统计始终是导入前的数字（实测 26 家 → 26 家），表格里也没有出现"杭州新元环保""绍兴越新纺织""宁波海川物流"。

期望　确认后把 3 行 push 进 ENT 并 render()，同时把校验阶段那 2 行（重复 + 缺名称）的处置结果写清楚。这是配置页最有说服力的一段流程，收尾断在这里很可惜。

D-13五处「复制」按钮其实没复制已修复总览弹窗 / 任务日志 / 明细弹窗 / AI 归档·文档·邮件

现象　点「复制路径」，按钮文案 1.5 秒后变回「复制路径」，中间的「已复制」是假的——全站没有任何 navigator.clipboard 或 execCommand('copy') 调用。用户粘贴出来还是上一次剪贴板的内容。

期望　补真复制（三行代码），失败时降级成"已选中路径，请手动复制"。

// 统一封装，五处调用同一个
function copyText(text, btn){
  var done = function(){ var t=btn.textContent; btn.textContent='已复制';
    setTimeout(function(){ btn.textContent=t; }, 1500); };
  if (navigator.clipboard && window.isSecureContext) {
    navigator.clipboard.writeText(text).then(done, fallback);
  } else fallback();
  function fallback(){
    var ta=document.createElement('textarea'); ta.value=text;
    ta.style.cssText='position:fixed;opacity:0'; document.body.appendChild(ta);
    ta.select(); try{ document.execCommand('copy'); done(); }
    catch(e){ btn.textContent='请手动复制'; }
    document.body.removeChild(ta);
  }
}

注意　file:// 打开时 isSecureContext 为 true 但剪贴板权限可能被拒，所以 fallback 分支必须有，否则本地演示会失败。

D-14浏览器前进/后退换不了页面，改 hash 也不跳已修复外壳 › 导航

现象　show() 用 history.replaceState 写 hash，历史栈里不留记录，所以后退直接退出页面；同时没有监听 hashchange，手动把地址改成 #ai 回车，界面还停在原来那页。

期望　改成 pushState + 监听 popstate/hashchange。对原型评审来说，能"发个带 #detail 的链接直接打开明细页"是很实用的能力（现在首次加载的 hash 深链是好的，坏的是运行中切换）。

window.addEventListener('hashchange', function(){
  var k = location.hash.replace('#','');
  if (TITLES[k] && k !== current) show(k);
});
// show() 内：history.replaceState → history.pushState
D-15六个页面各说各话，做完的事不会同步已修复外壳 ↔ 六个 iframe

现象　六个页面是六个独立 srcdoc iframe，彼此不通信：

  • 任务页把「运行全流程」跑完（4/4、邮件已发 3 人），总览仍是"AI 分析 未开始 / 待处理 20 家"，AI 页仍是"已完成 0 家"。
  • AI 页生成分析完成，总览的重点风险卡和"分析还没跑"的提示条不变。
  • 配置页新增/停用企业，明细页的 25 家不变。
  • 侧栏「数据源 25/25、23/25」是写死的，任务页"重新取数"跑完后不会动。

期望　原型阶段不必做真状态机，但至少要有一段 postMessage 广播（例如 {type:'flow-done'}）让总览/AI 页切到"已完成"文案。否则演示时必须回避"跑完之后呢"这个问题。

三 · 体验与适配 4 处

D-16手机宽度下「系统设置」的定时任务卡破版已修复系统设置 › 定时任务（390px 宽）

现象　外壳在 900px 以下已经切成了横向导航条（说明是打算支持手机的），但内嵌页面没有跟上：

  • 「已启用」文字压在开关上；「下次执行 2026-10-22 05:30」被挤成三行并压住上一个字段；
  • 「执行时间」的时间输入框被压成一个空白小方块，时间值看不见；
  • 「成功 · 4 分 12 秒」被右边界裁成「成功 · 4 分 1」。

期望　给 .mrow 这类两列字段加一个 640px 以下的单列断点（label 在上、值在下），以及 min-width:0 防止 flex 子项撑不开。取数·任务的来源卡片（超出 448px）、风险明细的等级行（超出 1033px）也有同样的横向溢出。

D-17弹窗打开后焦点还在页面上，也没有 dialog 语义已修复全部 6 个页面的弹窗

现象　企业弹窗打开后 document.activeElement 仍是 BODY；遮罩层没有 role="dialog"、没有 aria-modal；Tab 会跑到背后的页面上；关闭后焦点不回到触发它的那一行。

期望　打开时 focus() 到标题或第一个按钮、关闭时归还焦点、给遮罩加 role="dialog" aria-modal="true" aria-labelledby。现在唯一能关的方式是 Esc（还得焦点在 iframe 里）或点按钮，键盘用户很容易困住。

D-18明细页分布图每 6–10 秒自己翻页，停不下来已修复风险明细 › 风险分布轮播

现象　自动轮播只在 mouseenter 时暂停，没有播放/暂停按钮、不响应键盘焦点（focusin 不停），工具栏只写了"自动轮播"三个字。用户正在看"高风险 8 家"时会被翻走。

期望　加一个"暂停轮播"的开关（或改成默认不自动播，用户点圆点再动）；至少在 focusin 时暂停。同时尊重 prefers-reduced-motion。

D-19全站把滚动条宽度设成了 0已修复外壳 + 6 页公共样式

现象　::-webkit-scrollbar{width:0;height:0}。桌面上卡片内部滚动（长名单、日志）没有任何可视提示；一旦在窄屏出现横向溢出，用户也看不出"还能往右划"。

期望　保留视觉干净的取向，但给可滚动容器一个提示：内容溢出时加底部渐隐（mask-image）或"滚动查看更多"的细箭头；横向溢出的容器至少别把 height 也归零。

四 · 一致性与无障碍 6 处

D-20弱化文字的对比度只有 2.18:1已修复设计变量 --text-3 / --text-4

实测　白底上的对比度：--text-3 #8A9099 = 3.22:1、--text-4 #AAB0B9 = 2.18:1。WCAG AA 对小字要求 4.5:1。风险明细单页就有 133 个元素用 text-3、72 个用 text-4。

期望　把 text-3 提到 #6B7280（4.8:1）、text-4 提到 #808893（3.9:1，用于纯装饰性文字可接受）。这两个变量在 6 个页面里是统一的，改一处全站生效——是性价比最高的一条。

D-21只有总览页尊重「减少动态效果」已修复6 页 CSS

现象　prefers-reduced-motion 只在 overview 里写了 1 处，tasks / detail / ai / config / setting 都是 0。而 tasks 的全流程进度、detail 的轮播位移恰恰是动得最多的两处。

期望　把 overview 那段媒体查询提成公共样式块，6 个页面共用。

D-22AI 页提示条链接写着「去配置模型」，点了不跳配置已修复AI 与邮件 › 顶部提示条

现象　未分析时点这个链接，只弹一句"点「生成分析」即可开始"；分析完成后文案会变成「预览邮件」，行为也跟着变。也就是说这个链接的文案和行为是两套逻辑。

期望　未分析时文案改成「开始分析」并直接调 runAnalysis()；真要跳配置就用 data-nav 回配置页。文案说什么，就做什么。

D-23饼图扇区键盘够不着已修复风险明细 › 等级视图饼图

现象　扇区 tabIndex=-1，只能鼠标点。旁边的等级行（.l2r）有 tabindex="0" 和 Enter 处理，可替代，但两者视觉上不等价（旁边写着"点图例可筛选"）。

期望　给扇区 tabindex="0" + role="button" + Enter/Space，或干脆把文案改成"点右侧等级行筛选"。

D-24进度条与轮播没有语义已修复取数·任务 / AI 与邮件 / 风险明细

现象　全流程进度、AI 分析进度都是纯 div 宽度动画，没有 role="progressbar"/aria-valuenow；轮播没有 aria-live，翻页了读屏也不知道。

期望　进度条补 role="progressbar" 与三个 aria 值；轮播容器加 aria-live="polite"。

D-25导航项是没 href 的 a 标签已修复外壳 › 侧栏

现象　六个导航项是 <a class="item"> 不带 href，靠 tabindex="0" + keydown 才能用键盘。<a> 没有 href 不会被读屏当成链接，也不会被浏览器的"链接列表"收录。

期望　改成 <a href="#tasks">（顺便解决 D-14）或 <button aria-current="page">。选中态用 aria-current 而不是只加 .on 类。
