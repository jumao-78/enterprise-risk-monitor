# 一、简介

## 1.1 目的

本文档是企业风险监测系统的产品需求文档，用于确认本期需求范围、功能规则与界面交互，作为设计、开发、测试与验收的共同依据。

本文档只描述产品功能与交互，不涉及技术实现、算法选型与代码结构；技术细节见《开发实施说明书》，视觉细节见《UI 设计说明书 v3.0》。

本文档的主要读者为开发、测试与演示汇报人。功能规则以本文档为准；与既有材料冲突时，以本文档 1.2.4 列出的裁定结果为准。术语与指标口径见附件 8.2，数据构成与快照说明见附件 8.3。

## 1.2 范围

### 1.2.1 文档范围

本文档覆盖系统当前版本的全部 8 个功能模块：风险总览、取数与任务、风险明细、AI 分析与邮件、配置、系统设置、移动端、风险助手。每个模块展开到功能点级别，逐个给出用户场景、前置条件、流程、需求规则与边界处理。

本文档影响的对象包括：前端开发与联调、测试用例编写、界面验收、演示脚本编写与对外汇报口径。

界面原型已经存在，PC 端见 `企业风险监测_原型汇总.html`，移动端见 `企业风险监测_手机版.html`。本稿不再为界面留图位，只在附件 8.1 登记两张结构图；原型未覆盖的边界统一列在附件 8.4。

# 二、用户角色描述

系统有三类使用者，共用同一套数据与页面，差别在关注点与动作。

| 用户角色 | 用户描述 |
| 决策者（领导） | 关注「今天有没有问题、有多严重、比上一周期如何」。通过总览页的四卡 KPI、今日需处理名单与近七日趋势获得结论，通过邮件获得日报；不操作取数与配置。判断依据是风险等级分布、重点企业数量与环比变化 |
| 操作者（值班账号） | 关注数据跑没跑、卡在哪、怎么补。负责触发取数与全流程、处理失败重试、生成分析、发送邮件；判断依据是执行轨状态、错误条四要素与失败任务列表 |
| 维护者（与操作者为同一人） | 关注配置是否完整、存储是否健康。负责企业名单、AI 与邮件参数、定时任务、自检与清理；判断依据是配置状态点、自检六项结果与目录健康摘要 |

三者的信息层级不同：决策者看结论，操作者看状态与入口，维护者看配置完整性。本版本不设权限隔离，三个角色共用同一账号，角色区分只用于指导信息层级与文案。

# 三、产品概述

## 3.1 目标

业务方要求把分散在多个政府公示平台上的企业风险，汇总成一份能直接用于汇报的结论。原系统的风险明细页只给汇总数字，看不到具体记录；同一批数据里「条」与「家」两种口径混用，分项与合计对不上；风险分布图的维度没有定义，汇报时说不清风险集中在哪里。后果是被追问某家企业出了什么事时无法当场回答，报出的数字也无法自证。本版本在已完成原型的基础上重做信息层级与统计口径，把取数、标准化、分析、发信串成一条状态可见的闭环。

| 编号 | 目标 | 验证方式 |
| G-01 | 从总览的任一企业到该企业全部原始风险记录，点击不超过 2 次 | 在总览「今日需处理」点企业行，弹窗内可见按来源分组的全部记录 |
| G-02 | 打开总览 5 秒内判断当日有没有问题，不翻页、不点开弹窗 | 1440×900 下首屏同时可见四卡 KPI、执行链、状态提示条与 3 行待处理企业 |
| G-03 | 「条」只用于记录，「家」只用于企业；「应分析」固定用家 | 全文检索「应分析」，单位全部为家；KPI 主数字为 22 条、20 家 |
| G-04 | 一次完整演示（取数 → 分析 → 发信）在 2—4 分钟内跑完，进度可见到单家粒度；演示环境分析压缩到约 6 秒 | 取数进度显示「第 N/25 家 · 当前：企业名」；分析进度显示已完成与应分析的家数（N/20） |
| G-05 | 任一环节失败，页内可看到哪一步、重试几次、什么错、下一步点哪里 | 错误条四要素齐全；失败任务可单条重试 |
| G-06 | PC 与移动端同一指标的口径与单位一致 | 两端 KPI 均为 25 家、22 条、9 条、20 家；等级与三态文案一致 |

## 3.2 总体流程

系统按「两源取数 → 标准化入库 → 按企业分析 → 归档 → 发信」五个环节执行，每个环节的结果写入任务记录，页面从任务记录与风险记录读取状态。风险总览是渲染视图，不是执行节点。

> **图位 1：总体流程图（待补）**
> 建议画法：横向五段主链（信用中国取数、企查查取数、标准化入库、AI 分析、归档发信），两源取数并行后汇入标准化；每段下方引出一条失败分支，指向「任务记录置失败 + 页内错误条 + 重试入口」。

各环节的输入、输出与失败处理如下。失败不等于中断：除登录态失效外，单家失败不影响其余企业。

| 环节 | 输入 | 输出 | 失败时怎么办 |
| 信用中国取数 | 企业名单（启用 25 家）、快照或会话 | 原始结果、成功 / 失败 / 无权限计数、耗时 | 按错误类型分级重试；仍失败记为「未采集」，其余企业继续 |
| 企查查取数 | 企业名单、登录态 | 原始结果、无权限栏目清单 | 无权限不计入失败，标「无权限」；登录态失效立即中断并提示重新登录 |
| 标准化入库 | 两源原始结果、11 类归一化映射、等级映射表 | 去重后的风险记录、`is_new` 标记 | 单条字段缺失记为待补并保留原始文件；映射缺失时归入「其他」并在日志留痕 |
| AI 分析 | 企业风险记录、六维分析模板 | 每家企业一份结构化结论、MD 与 DOCX 文件 | 重试 3 次；仍失败计入「失败」独立计数，不并入未完成 |
| 归档与发信 | 分析文件、明细 xlsx、收件人 | 归档索引、邮件与发送记录 | 取数失败无数据不发信；分析失败但有数据发信并在正文顶部警示 |

流程上的四个可执行节点固定为「信用中国取数、企查查取数、AI 分析、邮件发送」，状态按数据日期与步骤记录，同一天同一步骤只有一条状态。

# 四、产品特性

## 4.1 风险总览

### 4.1.1 产品概述

总览页回答四个连续问题：今天有没有问题（四卡 KPI）、流程跑到哪一步（状态提示条与今日执行）、风险集中在哪（近七日趋势与风险构成）、先看哪几家（今日需处理）。四层信息自上而下排列，越靠上越接近结论，越靠下越接近证据。页面不承担操作职责，唯一的主按钮是生成分析按钮，其余动作都指向另外五个页面。

### 4.1.2 产品结构

1. 四卡 KPI：给出监测企业、风险记录、重点风险、应分析四个数，定当日态势。
2. 状态提示条：指出当前最早未完成的环节，并给出下一步入口。
3. 今日执行：展示四个执行节点的时间、计数与耗时，是流程状态的入口。
4. 近七日趋势与风险构成：趋势回答比上一周期如何，构成回答「集中在哪个等级、栏目、来源」。
5. 今日需处理：列出最多 3 家高风险企业，行点击打开企业明细弹窗。

### 4.1.3 状态说明

页面状态描述这一页当前能不能用，数据状态描述这一页的数字处于什么采集程度。两者分开写，避免把「没取到数」显示成「没有问题」。

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 加载中 | 当日数据请求未返回 | 四卡、图表、表格各自显示骨架占位，页头与筛选保留；不整页转圈 | 日期切换可用，其余动作禁用 |
| 正常 | 当日有取数记录且读取成功 | 按 4.1.4 完整呈现 | 全部 |
| 未取数 | 当日无取数记录 | 四卡主数字显示破折号，状态提示条指向「去取数」 | 去取数、切日期 |
| 空 | 企业名单为空 | 全页显示「尚未配置监测企业」，附配置入口 | 跳转配置 |
| 读取失败 | 接口报错或数据库不可用 | 页内错误条，写失败原因与重试入口；已加载内容保留 | 重试 |
| 历史日期 | 日期选择器切到非今日 | 页头出现「回到今日」，提示条文案随该日状态变化 | 回到今日、查看该日数据 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 相关区域如何显示 |
| 有取数有记录 | 正常数字 | 当日取数成功且存在风险记录 | 四卡、趋势、待处理全部正常 |
| 有取数无记录 | 0 条 | 取数成功，全部企业未检索到记录 | KPI 显示 0 条；待处理区显示「今日没有高风险企业」 |
| 未取数 | — | 当日无任务记录 | 四卡主数字为破折号，不显示 0；趋势不画当日柱 |
| 某源无权限 | 无权限 | 账号无该栏目权限 | 该源计数标「无权限」，不计入失败；等级列不显示「无」 |
| 部分企业未采集 | 未采集 | 单家取数失败 | 该企业不进入待处理列表；明细页对应来源列显示「未采集」 |

硬规则：未取数时四卡显示破折号，不显示 0；无权限与未采集不得显示为「无风险」；「等级 = 无」只出现在取数成功且无记录的情况。

### 4.1.4 特性说明

#### 特性 1：四卡 KPI 与口径

**用户场景**

早上打开系统，需要在 5 秒内判断今天有没有问题；汇报时直接引用四个数字，且经得起追问「这个数是条还是家」。

**输入 / 前置条件**

当日或所选历史日期存在取数结果。无取数结果时按 4.1.3 的未取数状态呈现。

**流程说明**

进入总览 → 按日期读取四卡数据 → 渲染主数字、脚注与构成条 → 切换日期时整页重绘 → 点「回到今日」恢复。

**需求描述**

界面与尺寸：四卡等宽四列，间距 13px；卡内依次为标签行、主数值（27px、字重 600）、脚注（11.5px）、构成条（高 4px、圆角 2、段间无缝）。四卡顺序固定为监测企业、风险记录、重点风险、应分析，不随数值大小重排。

数据与排序：主数字单位绑定如下，主数字后的单位字号 13px，基线上移 2px。构成条只在风险记录卡与重点风险卡显示，分段比例按记录数计算。

| 卡片 | 主数字口径 | 脚注 | 单位 |
| 监测企业 | 配置且启用的企业数 | 配置 N 家 / 已取 N 家 | 家 |
| 风险记录 | 两源去重后的记录条数 | 较上一周期 ±N 条、涉及 N 家企业 | 条 |
| 重点风险 | 等级为「高」的记录条数 | N 家企业、等级为高 | 条 |
| 应分析 | 当日有风险记录的企业数 | 已完成 N / 未完成 N | 家 |

规则与判定：环比按「近 7 天对比前 7 天」计算，切换到 30 天视图时按「近 30 天对比前 30 天」；风险记录下降显示绿色下箭头，上升显示红色上箭头，颜色只作辅助，箭头与数字必须同时存在；重点风险占比 = 高风险记录数 ÷ 记录总数，保留整数百分比；应分析为 0 时不显示完成率，改显示「无待分析企业」。

异常与边界：未取数时主数字显示「—」，脚注显示「今日尚未取数」，构成条隐藏；无历史数据时环比显示「—」；记录总数为 0 时占比不计算，显示「—」；数值超过 9999 时用千分位，不缩写为「万」。

**补充说明**

本版本不做四卡点击下钻。原因是四卡是结论不是入口，下钻统一走「今日需处理」的行点击与「风险构成」的「查看明细」，同页出现两条下钻路径会让演示时的点击顺序变得不确定。

#### 特性 2：状态提示条

**用户场景**

数据已经取回但分析还没跑，操作者需要知道现在该点哪里，而不是自己去四个页面找入口。

**输入 / 前置条件**

当日存在至少一个未完成环节，或存在部分失败。

**流程说明**

进入总览 → 读取取数、分析、邮件三段状态 → 取最早未完成环节生成文案 → 点击右侧按钮执行或跳转 → 环节完成后提示条消失。

**需求描述**

界面与尺寸：浅琥珀底 `#FFFCF6`，左侧 3px `#E29A2D` 竖条，圆角 9，内边距 10px 12px；主文案 12.5px、颜色 `#7A5314`；补充文案 11.5px、次级灰；右侧一个文字按钮或主按钮。整条高度不超过 44px。

数据与排序：同一时刻只显示一条提示，不并列；优先级为取数未完成 > 分析未完成 > 邮件未发送。提示条位置固定在四卡下方、今日执行上方。

规则与判定：文案按状态固定生成，必须指出具体缺哪一步，禁止使用「今日流程未完成」这类笼统表述。

| 状态 | 主文案 | 补充文案 | 按钮 |
| 未取数 | 今天还没取数。 | 25 家待取，预计 4 分钟。 | 去取数 |
| 已取未分析 | 数据已就绪，分析还没跑。 | 20 家待分析，预计 6 分钟。 | 生成分析 |
| 已分析未发信 | 分析已完成，邮件还没发。 | 3 位收件人、2 个附件。 | 发送邮件 |
| 全部完成 | 不显示提示条 | — | — |

异常与边界：取数部分失败时，主文案改为「2 家无权限，其余 23 家已入库。」，按钮改为「查看任务」；分析部分失败时，主文案改为「18 家完成、2 家失败。」，按钮改为「查看失败」；历史日期下按钮改为「回到今日」，不提供在该日期补跑。

**补充说明**

本版本不做常驻阻断横幅。原因是总览是汇报页，阻断横幅会遮挡 KPI，且失败详情已由取数页的错误条与失败任务区承担，重复提示会让页面看起来一直在报错。

#### 特性 3：今日执行

**用户场景**

汇报时被问「今天跑到哪一步」，或操作者判断现在能不能发信，需要一眼看到四个节点的状态与耗时。

**输入 / 前置条件**

当日存在任务记录。任务状态按「数据日期 + 步骤」存储，同一天同一步骤只有一条。

**流程说明**

进入总览 → 读取四节点状态 → 展示时间、计数与耗时 → 点「展开」查看该环节的企业级结果 → 点「查看任务」跳转取数页。

**需求描述**

界面与尺寸：四列等宽，内边距 14px 16px 15px；节点圆点 14px；环节名 13px、字重 500；时间 11.5px；计数行 11.5px；节点之间不画连接线。每个节点底部有「展开」文字链，展开面板位于轨道下方、整行宽度。

数据与排序：节点顺序固定为信用中国、企查查、AI 分析、邮件，不按耗时或状态重排。计数行格式为「成功 N / 失败 N　耗时」，企查查的无权限单独成项「成功 23 / 无权限 2」。

规则与判定：节点状态取四值「成功、部分完成、进行中、未开始」。AI 分析节点按完成家数判定：0 家为未开始，1—19 家为进行中，20 家全部成功为成功，存在失败为部分完成；邮件节点按发送记录判定：无记录为未开始，发送成功为成功，部分收件人失败为部分完成。

异常与边界：任务卡在「执行中」超过 30 分钟，节点显示琥珀叹号并附「疑似中断」，点击跳转取数页并高亮「重置中断状态」；无任务记录时四节点全部为未开始，时间显示「—」；某节点失败时显示红色叹号，展开面板保留错误摘要。

**补充说明**

本版本不做节点连线与整体进度条。原因是两源取数实际并行，连线会被读成串行依赖；整体进度已由取数页的状态句「本次运行 X/4 步完成」承担。

#### 特性 4：近七日趋势与风险构成

**用户场景**

领导问「比上周好还是差」「风险主要集中在哪个栏目」，需要在同一屏给出趋势与构成，而不是切三个页面。

**输入 / 前置条件**

至少 2 天存在取数记录。不足 2 天时趋势区显示「暂无趋势，需至少 2 天数据」。

**流程说明**

进入总览 → 默认近 7 天 → 切近 30 天 → 悬停某日查看当日新增与累计 → 点「查看明细」跳转风险明细并预置维度。

**需求描述**

界面与尺寸：趋势卡与构成卡两列并排，间距 13px；图表区高约 180px；柱为当日新增、折线为累计；柱色 `#C0483B` 20% 填充加实线边，折线 `#5B6270`、1.5px；趋势卡底部四指标一行四列，上边框 1px。构成卡内三段纵向堆叠，用 1px 分割线隔开，行高 26px。

数据与排序：四指标固定为峰值日期、较上一周期、涉及企业、七日均值。构成三段固定为按等级、按栏目、按来源；等级段按高、中、低、无顺序；栏目段按条数降序，同数按最高等级、再按名称；来源段固定信用中国在前、企查查在后。

规则与判定：较上一周期按「近 7 天对比前 7 天」，30 天视图按「近 30 天对比前 30 天」；峰值并列时取最近日期；七日均值 = 区间新增记录数 ÷ 区间天数，保留 1 位小数；构成占比按记录数计算，不按企业数；来源段脚注写明「两源重复信息 N 条，去重后 N 条」。

异常与边界：某日 0 条时画 2px 高的小墩，不画零高柱；区间内不足 7 天时只画有数据的天，均值按实际天数计算；区间内全部为 0 时显示「近 7 天无新增记录」；日期断档时断档日不画柱，折线跨过断档并在刻度上置灰；切换 30 天视图必须重新取数并重绘，不能只改选中态。

**补充说明**

本版本不做三视图同屏对比，趋势与构成固定并排。原因是 1440 宽下三块同屏会把每块压到 380px，栏目名与日期标签都会截断，轮播与并排二选一，本期选并排二块。原型中 30 天切换只改选中态，属演示取舍；正式版按本特性要求切换即换数据。

#### 特性 5：今日需处理

**用户场景**

汇报时先讲最严重的几家；操作者据此决定先看哪家企业的记录。决策者指着某家企业问「这家怎么回事」时，从这里进入明细。

**输入 / 前置条件**

当日存在等级为「高」的风险记录。

**流程说明**

进入总览 → 按综合等级与记录数取前 3 家 → 点行或「查看」打开企业明细弹窗 → 关闭后回到列表 → 点「查看全部 N 家企业」跳转风险明细并预置等级筛选。

**需求描述**

界面与尺寸：表格 6 列，列宽为企业名称 30%、等级 11%、来源 16%、风险摘要 19%、日期 12%、操作 12%；行高约 44px；表头 11.5px；最多 3 行，超出不滚动，由「查看全部」承接。

数据与排序：排序规则为综合等级由高到低，同级按记录条数降序，再按最近记录日期降序。等级列显示「高　2 条」，等级与条数之间用全角空格。来源列显示「信用中国 N　企查查 N」，某源无权限时写「无权限」。摘要列取该企业风险条数最多的栏目、取该栏目最近 1 条，双源记录追加「双源」标签。日期列取该企业最近一条记录的日期。

规则与判定：只列有风险记录的企业，红名单企业不进入；同一企业只出现一行；「今日需处理」的「今日」指所选数据日期，不指自然日；「查看全部 N 家企业」中的 N 为当日高风险企业数，不是记录条数。

异常与边界：无高风险企业时区块显示「今日没有高风险企业」并给「查看全部风险」入口；企业名超长时单行省略，悬停显示工商登记全称；明细读取失败时弹窗内显示失败原因与重试，不留空白；历史日期下「查看全部」置灰，因明细页只承载当日数据（见 8.4 第 6 项）。

**补充说明**

本版本不做行内展开。原因是一行展开多条会破坏「一行一家」的粒度，展开后的条数合计会与四卡的 22 条对不上，正是原版口径混乱的来源；追溯统一走弹窗。
## 4.2 取数与任务

### 4.2.1 产品概述

取数页回答三个问题：这次跑成功了吗（两源结果卡）、卡在哪一步（执行轨、状态句与错误条）、以前怎么跑的（任务历史）。三个问题对应三层信息：结果层给结论，状态层给原因，历史层给证据。页面允许干预，但所有干预都走二次确认，且不删除已入库数据。

### 4.2.2 产品结构

1. 两源结果卡：分别给出信用中国与企查查的栏目覆盖、四项计数、进度与环比。
2. 执行轨、状态句与错误条：串起四个节点的状态，并在失败时给出四要素说明。
3. 动作行：重置取数状态、重置中断状态、重新取数、运行全流程。
4. 失败任务与运行日志：列出失败企业，支持单条与全部重试，日志可查原始报错。
5. 任务历史：按步骤与状态筛选，支持分页与 CSV 导出。

### 4.2.3 状态说明

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 加载中 | 页面数据未返回 | 结果卡与历史区显示骨架，页头动作禁用 | 无 |
| 正常 | 当日任务已结束，无进行中任务 | 结果卡显示最终计数，执行轨显示四步状态 | 全部 |
| 执行中 | 存在状态为进行中的任务 | 结果卡显示进度「第 N/25 家」；动作行按钮禁用 | 查看日志 |
| 部分完成 | 至少一步成功、至少一步失败或无权限 | 状态句写明完成步数；错误条按需显示 | 重试、查看日志 |
| 失败 | 关键步骤失败或无数据 | 错误条常驻，写明四要素；结果卡标红 | 重试、重新取数 |
| 中断 | 任务停留在进行中超过 30 分钟 | 节点标「疑似中断」，动作行高亮「重置中断状态」 | 重置中断状态 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 相关列如何显示 |
| 成功 | 成功 | 该源全部启用企业取数成功 | 成功企业数、入库条数正常显示 |
| 部分成功 | 部分完成 | 有成功也有失败或无权限 | 分别列出成功、失败、无权限三项 |
| 无权限 | 无权限 ⚠ | 账号无该栏目权限 | 栏目 chip 虚线边框；不计入失败 |
| 未采集 | 未采集 | 采集失败，可重试 | 该企业来源列显示「未采集」 |
| 未开始 | — | 当日无该步骤任务 | 时间与耗时显示「—」 |

硬规则：无权限不计入失败；未采集不得显示为「无风险」；失败任务必须保留错误类型与尝试次数，不允许只显示「失败」。

### 4.2.4 特性说明

#### 特性 1：两源结果卡

**用户场景**

演示开始时，操作者需要说明「两个源各取回多少、哪家没权限、花了多久」；排障时需要判断是整源失败还是个别企业失败。

**输入 / 前置条件**

当日存在至少一次取数任务，或存在历史取数记录。

**流程说明**

进入取数页 → 读取两源任务结果 → 渲染栏目 chip、四项计数、进度条与环比 → 点「日志」查看原始输出 → 点「重新取数」走覆盖确认。

**需求描述**

界面与尺寸：两卡并排，间距 13px；卡头为源名（13.5px、字重 600）、状态标签、完成时间；栏目行 chip 高 20px、字号 11px、圆角 5；四项计数等宽，数值 17px、单位 11px；进度条高 4px；底部左为入库与重试摘要，右为两个按钮。栏目 chip 最多 6 个，其余折叠为「+N 类」，悬停展开完整名称。

数据与排序：四项计数固定为成功企业、失败、无权限、耗时，顺序不随数值变化；栏目 chip 按系统栏目顺序排列，不按条数排序。环比行格式为「较昨日　入库 +N 条　成功企业 持平」，风险记录增加用红色、减少用绿色。

规则与判定：无权限指账号无该栏目权限，不计入失败，也不计入成功；耗时取该源任务开始到结束的秒数，超过 60 秒显示「X 分 Y 秒」；进度文案为「第 N/25 家 · 当前：企业名」，N 为已处理家数，含成功、失败与无权限；「重新取数」是覆盖性操作，旧文件先备份到 `data/backup/`，命名 `{原名}.{YYYYMMDD-HHmmss}.bak`。

异常与边界：任务运行期间禁止再次触发，按钮禁用并提示「请等当前任务跑完」；成功企业为 0 时整卡加红色边框并显示「本次未取到数据」；文件被占用时跳过归档、记日志，并在页面提示「N 个未归档」；某源全部无权限时状态标签为「部分完成」，说明区写清影响企业名。

**补充说明**

本版本不做两源合并成一张卡。原因是两源的栏目权限与失败语义不同，合并后无权限会被平均成失败，看不出「是没权限还是没取到」。

#### 特性 2：执行轨、状态句与错误条

**用户场景**

演示中流程停在某一步，观众会问「为什么没继续」；操作者需要一句话说清完成了几步、失败几个、下一步点哪里。

**输入 / 前置条件**

当日存在任务记录。错误条只在存在失败任务时出现。

**流程说明**

进入取数页 → 读取四步任务状态 → 渲染执行轨与状态句 → 有失败时在页头下方渲染错误条 → 点错误条右侧按钮重跑该步。

**需求描述**

界面与尺寸：执行轨四步横排，圆点 14px、步骤名 12.5px、时间 11.5px；右上角显示「下次自动运行 明天 05:30」，时间加粗；状态句 12.5px，数字加粗；错误条左侧 3px `#C2261B` 竖条、底色 `#FEF2F2`、圆角 9，主文案 12.5px、建议 11.5px。

数据与排序：步骤顺序固定为信用中国取数、企查查取数、AI 分析、邮件发送；状态句句式固定为「本次运行 X/4 步完成，N 个失败任务；两源入库 N 条（去重 N 条）；企查查『经营风险』无权限 N 家。」，无某项时省略该分句，不写「无」占位。

规则与判定：错误条必须含四要素——哪一步失败、重试几次、错误类型、建议动作，缺一项则不显示错误条并改为状态句提示。错误类型枚举为网络异常、认证失败、验证码未通过、配置缺失、上游返回空内容、超时。建议动作必须可点击，且指向能解决该错误的位置。

异常与边界：多步失败时只显示最早一步，末尾追加「另有 N 步失败」，点击展开其余；无失败时错误条不占位；失败但已有入库数据时，错误条末尾补一句「已入库的 N 条记录不受影响」；任务进行中错误条不显示，避免与进度冲突。

**补充说明**

本版本不做全站阻断横幅。原因是阻断横幅会遮挡所有页面，而单步失败不影响已入库数据的浏览与发信；失败可见性由页内错误条与托盘通知承担。

#### 特性 3：动作行与两个重置

**用户场景**

演示前发现今天的取数标记还在，需要重跑；或任务卡在「执行中」不动，需要把锁释放掉。两个动作看起来都像「重置」，实际后果完全不同。

**输入 / 前置条件**

「重置取数状态」要求当日存在取数标记；「重置中断状态」要求存在进行中的任务；「重新取数」要求当前无运行中任务。

**流程说明**

点按钮 → 弹出二次确认（写明后果与可恢复性）→ 确认 → 执行 → 页面提示结果并刷新任务状态。取消则不改动任何数据。

**需求描述**

界面与尺寸：动作行位于执行轨下方，三个按钮横排，间距 8px；「重置中断状态」用白底红字红边，其余为描边按钮；按钮下方一行说明 11.5px，解释两个重置的差别，并写明「任务运行期间无法再次触发取数」。

数据与排序：按钮顺序固定为重置取数状态、重置中断状态、查看取数结果；「重新取数」在两张源卡底部，各自独立。

规则与判定：两个重置语义不同，不可合并。「重置取数状态」只清除「今日已取过」标记，已入库记录不删；「重置中断状态」把卡在「执行中」的任务改判为失败并释放锁，不删除任何数据。二次确认文案固定：

| 操作 | 确认文案 |
| 重置取数状态 | 将清掉今日取数标记，已入库的 22 条记录不受影响。确认重置？ |
| 重置中断状态 | 仅在任务异常卡住时使用。将把执行中的任务改判为失败并释放锁。确认？ |
| 重新取数 | 将覆盖今日已取数据，旧文件备份至 backup。确认重新取数？ |
| 运行全流程 | 将按「取数 → 分析 → 发信」顺序执行，耗时约 6 分钟。确认开始？ |

异常与边界：无今日取数标记时「重置取数状态」禁用，悬停说明「今日尚未取数」；无进行中任务时「重置中断状态」禁用；「运行全流程」在任一步进行中禁用；重置后任务历史新增一条记录，操作人记为值班账号。

**补充说明**

本版本不提供「跳过失败企业继续」开关。原因是跳过会让当日总数与企业名单不一致，且跳过的企业在明细页无法区分「没查」与「查了没有」，破坏三态口径。

#### 特性 4：失败任务与运行日志

**用户场景**

演示中某几家企业分析失败，需要当场重试；若重试仍失败，需要打开日志确认是接口返回空还是超时，以便向观众解释。

**输入 / 前置条件**

存在状态为失败的任务记录。日志文件位于 `data/task_logs/`。

**流程说明**

页面出现失败任务区 → 查看失败企业、错误类型与尝试次数 → 点单条「重试」或「全部重试」→ 二次确认（全部重试时）→ 执行并刷新状态 → 点「日志」打开运行日志弹层。

**需求描述**

界面与尺寸：失败任务表 5 列，列宽为时间 12%、步骤 14%、企业 34%、错误类型 22%、尝试 8%、操作 10%；行高 44px；最多 5 行。日志弹层最大高度 60vh，内容区等宽字体、失败行标红，底部显示日志路径与「复制路径」。

数据与排序：按时间倒序排列，同一时间按企业名升序；尝试次数取该任务累计重试次数，最大 3 次；错误摘要截取原始报错前 60 字，完整内容在日志中。

规则与判定：重试策略按错误类型分级——网络异常与页面未加载重试 3 次；验证码未通过重试 2 次后转人工；登录态失效不重试，立即中断并提示重新登录；配置缺失不重试，直接指向配置页。单次取数超时 10 分钟，三次重试总上限 30 分钟。重试为幂等操作，同一条记录重复重试不产生重复入库。

异常与边界：失败超过 5 条时，表尾显示「还有 N 条，看日志」；重试仍失败时保留原错误类型并累加尝试次数，不覆盖首次失败原因；日志文件缺失时提示「日志已归档或清理」，给出去向；「全部重试」需二次确认，文案写明将重试的企业数。

**补充说明**

本版本不做自动定时重试。原因是验证码与登录态需要人工介入，自动重试会连续触发风控，导致账号被临时限制，反而延长恢复时间。

#### 特性 5：任务历史

**用户场景**

领导问「昨天几点跑的、跑了多久」，或排障时需要确认同一错误是否反复出现，需要按步骤与状态回看历史。

**输入 / 前置条件**

存在任务记录。记录按「数据日期 + 步骤」唯一。

**流程说明**

进入取数页 → 滚动到任务历史 → 选择步骤与状态 → 翻页 → 点「导出 CSV」导出当前筛选结果。

**需求描述**

界面与尺寸：筛选行两个下拉（全部步骤、全部状态）加右侧计数「共 N 条」；表格 7 列，列宽为时间 15%、数据日期 12%、步骤 17%、状态 11%、耗时 11%、尝试 7%、错误摘要 27%；每页 5 条，底部分页显示「第 1–5 条，共 12 条」。

数据与排序：按时间倒序，同时间按步骤顺序；步骤枚举为信用中国取数、企查查取数、AI 分析、邮件发送；状态枚举为成功、部分完成、失败；错误摘要无内容时显示「—」。

规则与判定：筛选条件之间为「且」关系；导出 CSV 含当前筛选结果的全部列，编码 UTF-8 带 BOM，保证 Excel 打开中文不乱码；分页不改变排序。

异常与边界：无符合条件的记录时，表内显示一行「没有符合条件的任务记录」并附「清空筛选」；记录超过 1000 条时提示按日期筛选，不提供无限滚动；导出时无数据则按钮禁用。

**补充说明**

本版本不做历史删除。原因是任务历史是留痕依据，本地单机每日最多新增 4 条，一年约 1460 条，存储压力可忽略；删除入口会削弱可追溯性。
## 4.3 风险明细

### 4.3.1 产品概述

风险明细回答三个递进的问题：整体风险集中在哪（分布图）、哪几家企业有问题（企业表）、这家企业究竟出了什么事（明细弹窗）。三层信息分别对应全局、名单与证据，缺一层就会出现「看得到总数、看不到人」或「看得到人、说不出事」的断层。表格粒度是「一行一家企业」，这是本模块所有口径的基准。

### 4.3.2 产品结构

1. 风险分布三视图：企业、栏目、等级三个视图轮播，用于判断集中度与切筛选。
2. 筛选行与栏目分组：按日期、栏目、关键词、等级、是否含无记录企业过滤名单。
3. 企业明细表：一行一家企业，给出综合等级、两源采集状态、风险摘要与查看入口。
4. 企业明细弹窗：展示单家企业全部记录，按来源分组，标注双源印证，附 AI 摘要。
5. 导出 Excel：把当前筛选结果导出为当日明细表，页脚带演示声明。

### 4.3.3 状态说明

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 加载中 | 明细数据未返回 | 分布区与表格显示骨架，保留表头与筛选 | 筛选可用，行不可点 |
| 正常 | 读取成功且当前筛选有结果 | 按 4.3.4 完整呈现 | 全部 |
| 空结果 | 读取成功，当前筛选无匹配 | 表格整行合并显示「这个筛选下没有记录。」并回显筛选与「清空筛选」 | 清空筛选 |
| 全量无数据 | 当日未取数或企业名单为空 | 分布区显示「今日尚无取数结果」，表格不渲染 | 去取数、跳转配置 |
| 读取失败 | 接口报错 | 页内错误条，写失败原因与重试 | 重试 |
| 历史日期 | 切到非今日 | 日期按钮文案更新；表格数据按该日期取（正式版要求） | 回到今日 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 等级列如何显示 |
| 有风险记录 | N 条 | 采集成功且检索到记录 | 该企业最高档等级 |
| 未发现风险记录 | 未发现 | 采集成功，未检索到记录 | 无 |
| 未采集 | 未采集 | 采集失败，可重试 | — |
| 无权限 | 无权限 | 账号无该栏目权限 | — |

硬规则：三者视觉必须可区分，禁止统一显示为 0 或「无」。「等级 = 无」只出现在采集成功且无记录的情况；采集失败或无权限时等级列显示破折号，避免把「没查到」误读为「没问题」。无权限不计入失败，也不参与等级分布统计。

### 4.3.4 特性说明

#### 特性 1：风险分布三视图

**用户场景**

汇报开场需要一句话说清「风险集中在哪」：按企业看是集中在少数几家，按栏目看是集中在失信被执行，按等级看是高等级占四成。

**输入 / 前置条件**

当日存在风险记录。三个视图共用同一份数据，切换不重新请求。

**流程说明**

进入明细页 → 默认停在企业视图 10 秒 → 自动切到栏目视图，停留 6 秒 → 切到等级视图，停留 6 秒 → 循环。悬停、拖拽、滚动或弹窗打开时暂停；移出 3 秒后恢复；手动切换后 10 秒内不自动切。

**需求描述**

界面与尺寸：卡片高约 300px，横向轨道三屏等宽（各 33.3333%），位移过渡 420ms；顶部右侧有「暂停轮播 / 恢复轮播」按钮；底部三枚指示器 6×6，当前项为 20×6 长条，命中区 24×24。三个视图形态不同：企业视图为四栏分组列表，栏目视图为纵向堆叠柱（柱宽 30），等级视图为环形图加右侧行表。

数据与排序：企业视图四栏固定为高风险、中风险、低风险、未发现记录，列头显示「N 家 · N 条」，未发现组不显示条数；组内按条数降序、同条数按最近日期降序。栏目视图按总条数降序，同数按最高等级、再按名称。等级视图按高、中、低顺序，不显示「无」。

规则与判定：停留时长为企业 10 秒、栏目 6 秒、等级 6 秒；首屏进入先停 10 秒再开始轮播；横向拖拽位移超过 40px 判翻页，松手吸附；键盘左右方向键在视口获得焦点后可切视图；占比按记录数计算，不按企业数，标题旁注明「22 条风险记录、20 家企业，占比按记录数」。

异常与边界：某视图无数据时显示「该维度暂无数据」，轮播继续；三个视图都无数据时不轮播，固定显示空态；只有一个视图有数据时停在有数据的视图；用户正在拖拽时暂停计时，松手后重新计时。

**补充说明**

本版本不做三视图同屏对比。原因是 1440 宽下三块同屏每块只有约 380px，栏目名与图例都会截断；轮播保证单屏可读，且演示时可以按讲解节奏停留。

#### 特性 2：筛选行与栏目分组

**用户场景**

领导只关心「经营异常」这一类，或只想看某家企业；操作者需要把 11 类栏目按等级分组后快速定位。

**输入 / 前置条件**

当日存在企业名单与风险记录。

**流程说明**

选择日期 → 选择栏目（可搜索）→ 输入关键词 → 由图表点击带入等级 → 切换是否含无记录企业 → 表格实时刷新 → 点「清空筛选」恢复默认。

**需求描述**

界面与尺寸：筛选行依次为数据日期、全部栏目下拉、搜索框（宽 258px）、等级（默认隐藏）、含无记录企业开关、右侧计数「当前 20 家 / 共 25 家」。栏目下拉面板含搜索框与三个分组，分组标题不可点击；每项右侧显示条数，末尾为「全部 22」。

数据与排序：栏目下拉按等级分三组——高风险 4 类（失信被执行、严重失信、破产重整、吊销注销）、中风险 4 类（经营异常、股权冻结、限制高消费、税务违法）、低风险 3 类（行政处罚、司法案件、股权出质），共 11 类。分组顺序固定，不按条数重排。

规则与判定：多个条件之间为「且」；搜索覆盖企业名、栏目名、决定机关、描述、来源五个字段，为子串匹配，输入后 300 毫秒触发；「含无记录企业」关闭时只显示有记录企业（20 家），打开后显示全部启用企业（25 家）；从图表点击带入的等级显示为「等级 高」并可单独清除；切换日期必须重新取该日数据，不能只改按钮文案。

异常与边界：筛选无结果时表格显示空态并回显当前筛选；无跑批记录的日期在日期选择器中置灰不可选；搜索关键词超过 50 字时截断并提示；同时存在栏目与等级筛选时，计数显示的是交集。

**补充说明**

本版本不做拼音与分词搜索。原因是本期只有 25 家企业、22 条记录，三字段子串匹配已能覆盖；引入分词会把「华远」与「华源」这类名称混为一条，演示时反而造成误判。

#### 特性 3：企业明细表

**用户场景**

决策者要一份「哪几家有问题、多严重」的名单；操作者要据此判断先看哪家。表格是名单，不是记录清单。

**输入 / 前置条件**

当日存在企业名单与采集状态。默认只显示有记录企业。

**流程说明**

进入明细页 → 按默认排序渲染 20 家 → 调整筛选 → 点行或「查看」打开明细弹窗 → 关闭返回原位置与滚动位置。

**需求描述**

界面与尺寸：表格 6 列，列宽为企业名称 29%、综合风险 11%、信用中国 11%、企查查 11%、风险摘要 26%、明细 12%；行高约 48px；企业名称左侧 3px 等级竖条；表头 11.5px；表格底部左侧「显示 20 家　记录 22 条」，右侧「记录明细见导出文件，或点行查看」。

数据与排序：一行代表一家企业。综合风险取该企业所有记录中的最高档，标签后跟条数，格式为「高　2 条」。两源列按三态显示：有记录显示「N 条」，无权限显示「无权限」，无记录显示「未发现」，采集失败显示「未采集」。摘要列取主栏目前 1 条描述，单行截断，悬停显示全文；未生成分析时显示「待分析」。默认排序为综合等级由高到低，同级按条数降序，再按最近日期降序。

规则与判定：红名单企业不进入风险记录表，若打开「含无记录企业」则以「无风险记录」呈现；综合等级为「无」时排在有等级企业之后；「明细」列只显示「查看」二字，不带条数；等级竖条颜色只作辅助，等级文字必须同时存在。

异常与边界：未采集与无权限行的等级列显示「—」，且不计入等级分布；企业超过 50 家时分页，每页 50 行（原型未定义，本稿定义）；企业名超过 20 字时单行省略，悬停显示全称；表格读取失败时保留表头并显示重试行。

**补充说明**

本版本不做表格内展开行。原因是「一行一家」是本模块的口径基准，展开会让条数合计与总览 22 条对不上；追溯统一走弹窗，且弹窗内按来源分组，能直接回答「这条是哪来的」。

#### 特性 4：企业明细弹窗

**用户场景**

决策者指着某家企业问「这家怎么回事」。需要在一次点击内看到该企业全部原始记录、两条来源是否互相印证、AI 怎么解读。

**输入 / 前置条件**

目标企业至少存在一条风险记录，或至少存在一个采集状态。

**流程说明**

点行或「查看」→ 弹窗居中打开，背景加遮罩 → 内容区按来源分组渲染 → 滚动查看 → 点「详情」展开单条原文 → 关闭（右上 ✕、遮罩、ESC 三种方式）→ 焦点回到原行。

**需求描述**

界面与尺寸：弹窗宽 760px，最大高度为视口 82%，圆角 12；标题区与底部固定，中间内容区纵向滚动。标题为企业全称（15px、字重 600）加演示徽标；汇总行为「信用中国 N 条　企查查 N 条　去重后 N 条」；每个来源分组标题 12.5px、字重 600，无数据源不显示该分组；条目左侧 3px 等级竖条，栏目名 13px，后接等级标签与日期，描述 12px；底部左侧为导出文件路径，右侧「复制路径」「关闭」。

数据与排序：条目按日期倒序，同日期按等级降序；每条显示栏目、等级、日期、决定机关、描述与「详情」；双源记录在栏目名后加「双源」标签；分组顺序固定信用中国在前、企查查在后；AI 摘要位于所有分组之后，独立分区。

规则与判定：去重键为「企业 + 风险类型 + 发生日期 + 决定机关」，机关缺失时用描述前 20 字兜底；重复记录只保留一条，来源集合保留全部来源，来源为两个时标「双源印证」；「复制路径」后按钮文案变「已复制」并保持 1.5 秒；AI 摘要只解读、不给出等级，等级以条目标签为准。

异常与边界：单源无权限时分组标题右侧标「无权限」，不显示空列表；该企业当日无记录时显示「该企业今日未发现风险记录」；AI 摘要缺失时显示「尚未生成分析」并给「生成分析」入口；记录超过 50 条时内容区虚拟滚动，标题与底部保持固定；弹窗打开时背景页面不滚动。

**补充说明**

本版本不做上一家 / 下一家导航。原因是弹窗的关闭语义是「回到名单」，加上下家会在误点时串到另一家企业，汇报场景下会答错对象。

#### 特性 5：导出 Excel

**用户场景**

汇报后需要把明细发给同事核对，或作为邮件附件留档；对方要在 Excel 里按企业筛选。

**输入 / 前置条件**

当前筛选结果至少有一条记录。

**流程说明**

点页头「导出 Excel」→ 生成当日明细表 → 浏览器下载 → 打开核对页脚声明。

**需求描述**

界面与尺寸：页头右侧描边按钮「导出 Excel」，与页头动作区其他按钮同高 34px；下载文件名为 `风险明细_YYYY-MM-DD.xlsx`，日期取当前数据日期。

数据与排序：导出当前筛选结果，未筛选时为当日全量（20 家、22 条）；列与企业明细表一致，另加「统一社会信用代码」「决定机关」「记录日期」三列；每行一家企业，条数用分号分隔多条记录摘要；首行为表头，冻结首行。

规则与判定：页脚固定写「本文件为演示数据，不作为对外结论使用」并附数据日期与来源；单位与企业明细表一致，企业用家、记录用条；导出不改变页面筛选状态。

异常与边界：当前筛选无记录时按钮禁用，悬停说明「当前筛选无记录」；文件被占用导致写入失败时提示「请关闭已打开的 Excel 后重试」；导出耗时超过 3 秒时按钮显示「正在导出…」并禁用。

**补充说明**

本版本不做逐条记录一行的工作表。原因是对外核对以企业为单位，逐条展开会产生 22 行但无法直接看出「一家几条」；逐条原文在明细弹窗与邮件附件 DOCX 中可查。
## 4.4 AI 分析与邮件

### 4.4.1 产品概述

AI 与邮件模块回答三个问题：分析跑到哪了（运行卡）、分析结果在哪（归档）、日报发出去没有（发送记录）。三块信息按「执行 → 产物 → 投递」排列，对应操作者的动作链，也对应决策者收到的那封邮件。AI 只做解读，不做定级；等级永远由 11 类栏目映射表计算。

### 4.4.2 产品结构

1. 运行卡与四指标：展示本期企业、应分析、已完成、失败，并承载「生成分析」与「发送邮件」。
2. 分析归档：按日期列出已生成的分析文件，支持查看、复制路径与删除。
3. 邮件发送与记录：按发送批次列出状态、收件人、主题与附件，支持预览。
4. 三类预览弹层：分析文档、邮件正文、附件内容，均在页内查看，不下载即可核对。

### 4.4.3 状态说明

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 加载中 | 数据未返回 | 运行卡与两张表显示骨架，两个按钮禁用 | 无 |
| 未开始 | 当日有取数、无分析任务 | 提示条显示「今日分析尚未开始」，四指标已完成为 0 | 生成分析、发送邮件 |
| 进行中 | 存在进行中的分析 | 进度条显示「正在分析 N/20 家」，两个按钮禁用并显示「分析中…」 | 查看归档 |
| 已完成 | 20 家全部生成 | 提示条切换为「分析已完成，邮件还没发」或隐藏 | 发送邮件、预览 |
| 部分失败 | 有成功也有失败 | 失败计数变红，列头下加 2px 红线 | 重试失败项、发送邮件 |
| 不可用 | 未配置 API Key 或取数无数据 | 运行卡提示缺失项；发送邮件禁用 | 跳转配置、去取数 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 四指标如何显示 |
| 已完成 | 已完成 | 该企业分析文件已生成并落盘 | 计入已完成 |
| 失败 | 失败 | 重试 3 次后仍无有效输出 | 独立计数，不并入未完成 |
| 未完成 | 未完成 | 尚未开始分析 | 未完成 = 应分析 − 已完成 − 失败 |
| 无分析必要 | — | 该企业当日无风险记录 | 不计入应分析 |

硬规则：失败必须独立计数，不能并入「未完成」；「本期企业」为 25 家，「应分析」为 20 家，两者不可混用；无分析结果时点「发送邮件」必须先分析再发，不得报错要求用户先分析。

### 4.4.4 特性说明

#### 特性 1：分析运行与四指标

**用户场景**

演示中需要现场生成 20 家企业的风险摘要，并让观众看到进度；操作者需要知道哪几家失败，而不是只知道「没跑完」。

**输入 / 前置条件**

当日已取数且有风险记录；AI 配置完整（API Key、Base URL、模型、Max Tokens）。

**流程说明**

点「生成分析」→ 弹出确认弹窗（企业数、预计耗时、演示说明）→ 确认后自动跳转本页并开始 → 进度逐家更新 → 完成后四指标与提示条同步刷新。

**需求描述**

界面与尺寸：运行卡一行四指标，标签 11.5px、数值 22px、字重 600；「失败」列数值非 0 时变红并在列头下加 2px 红线；右侧两个按钮，「发送邮件」为描边，「生成分析」为墨底；按钮下方为进度条（高 4px）与状态文案。确认弹窗宽 432px，标题「生成 AI 分析」，正文写明企业数与去向，底部左侧「20 家 · 约 6 秒」，右侧「取消」「开始分析」。

数据与排序：四指标顺序固定为本期企业、应分析、已完成、失败；本期企业取当日已取数企业数（25），应分析取当日有风险记录的企业数（20）；进度文案为「正在分析 N/20 家」，N 为已完成家数。

规则与判定：分析粒度按企业，一家一份摘要；并发固定为 4（可配范围 1—8）；模型为 `deepseek-flash`，Max Tokens 为 4000；AI 输出只解读、不定级，输出契约中禁止出现等级字段，代码层校验不通过则视为失败并重试 1 次，仍失败走规则兜底；运行期间两个按钮禁用，文案变「分析中…」。

异常与边界：应分析为 0 时「生成分析」禁用，提示「今日无需分析」；分析中切走页面，任务继续，返回时按 3 秒轮询恢复进度；单家超时 60 秒计为失败；全部失败时进度条置红并提示「检查 AI 配置后重试」；未配置 Key 时按钮禁用并给出配置入口。

**补充说明**

本版本不做按企业勾选分析。原因是「已完成 N/20」的分母是应分析企业数，允许勾选会让同一页出现两个分母，汇报时说不清完成率。

#### 特性 2：分析归档

**用户场景**

领导临时要看某天的分析原文，或需要把 DOCX 作为邮件附件核对；操作者需要确认文件到底落在哪个目录。

**输入 / 前置条件**

存在至少一份已生成的分析文件，文件索引已写入归档表。

**流程说明**

滚动到分析归档 → 按生成时间倒序浏览 → 点「查看」打开文档预览 → 点「复制路径」复制本地路径 → 点「删除」走二次确认（仅 30 天前）。

**需求描述**

界面与尺寸：表格 5 列，列宽为生成时间 16%、数据日期 11%、来源 13%、文件路径 40%、操作 20%；路径列中间省略，悬停显示全文；操作列右对齐「查看」「复制路径」「删除」。标题行显示「共 N 份　显示最近 4 份」与「打开目录」。

数据与排序：按生成时间倒序；来源列显示模型名；路径格式为 `data/ai_analysis/YYYY/MM/YYYY-MM-DD_风险分析.md`，DOCX 同名不同扩展名；同一数据日期只保留一份最新归档，重复生成覆盖并更新生成时间。

规则与判定：删除仅对生成时间超过 30 天的归档开放，不足 30 天的「删除」置灰，悬停提示「仅可删除 30 天前的归档（本份 N 天前）」；删除需二次确认，确认文案写明文件将移入回收目录；删除写日志，记录时间、文件、操作人；复制路径后按钮文案变「已复制」1.5 秒。

异常与边界：文件索引存在但磁盘文件缺失时，该行标「文件缺失」并给「重新生成」入口；目录不可写时提示「归档目录不可写，请检查磁盘权限」；同一天重复生成时旧文件移入回收目录，不直接覆盖删除。

**补充说明**

本版本不做批量删除。原因是归档是分析结果的留痕，批量删除难以逐份核对，且 30 天限制已能控制容量。

#### 特性 3：邮件发送与发送记录

**用户场景**

演示最后一步是把日报发给 3 位收件人；操作者需要确认发给了谁、主题是什么、附件是否齐全、有没有人被退信。

**输入 / 前置条件**

邮件配置完整（SMTP、端口、账号、授权码、收件人）；当日有取数数据。

**流程说明**

点「发送邮件」→ 若尚无分析结果则先自动分析 → 演示环境下弹出「当前为演示快照，确认继续？」→ 发送 → 生成发送记录 → 点主题或附件打开预览。

**需求描述**

界面与尺寸：发送记录表 6 列，列宽为发送时间 15%、数据日期 11%、状态 10%、收件人 12%、主题 30%、附件 22%；状态为「成功」或「部分成功」，部分成功用琥珀色并在悬停说明失败对象与原因；收件人显示「3 人」，部分失败显示「2 成功 / 1 失败」；主题可点击打开邮件预览，附件可点击打开附件预览。

数据与排序：按发送时间倒序；主题格式固定为 `[演示]【企业风险监测】YYYY-MM-DD · 高风险 N 家 · 新增 N 条`，非演示环境去掉 `[演示]` 前缀；附件固定两个：`风险分析报告_{日期}.docx` 与 `风险明细_{日期}.xlsx`。

规则与判定：取数失败且无任何数据时不发信；分析失败但有数据时照常发信，并在正文顶部加醒目警示，写明「N 家中 M 家完成」；无分析结果时点发送，先自动完成分析再发送，不报错；发送前演示环境必须二次确认；同一数据日期允许重复发送，每次生成独立记录，不覆盖历史。

异常与边界：SMTP 认证失败时提示「SMTP 认证失败，QQ 邮箱请使用授权码」并给配置入口；部分收件人失败时状态为「部分成功」，重发只针对失败地址；附件生成失败时中止发送并保留已生成的分析，提示「附件生成失败，未发送」；发送超时 30 秒提示可重试，重试前先查发送记录避免重复投递。

**补充说明**

本版本不做短信或企业微信同步发送。原因是每增加一个通道都要独立处理失败、重试与对账，本期只有邮件一个通道，先把投递成功率做稳。

#### 特性 4：三类预览弹层

**用户场景**

发信前需要核对正文措辞与附件内容；领导问「邮件里写了什么」时，需要当场展示，而不是打开邮箱。

**输入 / 前置条件**

存在分析文件、发送记录或附件文件。

**流程说明**

点「查看」或主题、附件名 → 弹层打开 → 阅读或滚动 → 点「复制正文」「下载」或「关闭」。

**需求描述**

界面与尺寸：三个弹层共用一套外壳，最大高度 82vh，头部固定，底部固定。分析文档弹层渲染 Markdown 正文，底色为页面底色、圆角 8；邮件预览弹层上部为字段区（发件人、收件人、主题、时间），下部为纸张区（白底、内边距 24px、正文 12.5px、行高 1.8）；附件预览中 xlsx 显示前 10 行并注明「仅预览前 10 行」，docx 渲染正文。

数据与排序：邮件预览的字段顺序固定为发件人、收件人、主题、时间；附件预览先列工作表名，再列表头与数据行；文档预览保留标题层级与列表。

规则与判定：预览内容必须与归档文件一致，不做二次排版；「复制正文」复制纯文本，不复制 HTML 标签；「下载」下载原文件，文件名与附件名一致；预览不改变发送状态。

异常与边界：文件缺失时提示「文件已归档或清理」并给路径；Markdown 渲染失败时退化为纯文本，保证可读；附件超过 10MB 时只预览不自动下载；弹层打开时背景不滚动。

**补充说明**

本版本不做邮件正文在线编辑。原因是正文由模板与规则生成，允许编辑会让发出的内容与归档文件不一致，后续追溯无法对齐。

## 4.5 配置

### 4.5.1 产品概述

配置页把「系统能跑起来要填的东西」集中到一处：数据来源只读展示当前口径，AI 与邮件给出可测试的参数，企业名单决定监测范围。三块配置的共同要求是「改完能验证」——AI 有连通性测试，邮件有测试邮件，企业名单有唯一键校验。

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |

| 只读 | 数据来源卡 | 卡头标「只读」，无切换入口 | 查看 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 相关字段如何显示 |
| 已配置 | 已配置 | 必填项齐全 | Key 与授权码掩码，只露后 4 位 |

### 4.5.4 特性说明

#### 特性 1：数据来源（只读）

**用户场景**

演示前需要确认「这份数据是哪天、从哪来、多少家、多少条」；被问「能不能切实时」时，需要明确回答当前不支持界面切换。

**输入 / 前置条件**

存在快照数据集与元信息文件。

**流程说明**

进入配置页 → 查看数据来源卡 → 核对快照日期、规模与源站 → 点源站 chip 查看全称。

**需求描述**

界面与尺寸：字段采用两列成对布局，标签右对齐、宽 84px、11.5px，值 12.5px；源站用 chip 列表，字号 11px、圆角 5；卡头右侧为「只读」标签与「不提供切换」灰字。

数据与排序：字段固定为当前模式、快照日期、规模、名单构成、真实源站。规模写明「25 家企业、22 条风险记录、3 条双源印证」；名单构成为「失信公示 20 家　守信红名单 5 家」。

规则与判定：本卡只读，界面不提供切换入口，切换数据来源需修改服务端配置并重启；卡内文案必须与侧栏演示卡、数据来源弹层一致，三处任何一处改动需同步；快照日期取数据集元信息，不取当前时间。

异常与边界：快照缺失时显示「未检测到快照」并给出目录路径；元信息字段缺失时显示「—」，不猜测补全；源站链接不可达时 chip 仍显示名称，不做连通性校验。

**补充说明**

本版本不做界面切换数据源。原因是切换需要改服务端配置并重启，界面切换会造成「点了没生效」的误解，演示时反而增加解释成本。

#### 特性 2：AI 配置

**用户场景**

换一台机器部署或 Key 失效时，需要在这里重新填写并当场验证能不能通，而不是等到生成分析时才发现。

**输入 / 前置条件**

已开通模型服务并取得 API Key。

**流程说明**

填写 API Key、Base URL、模型、Max Tokens、并发数 → 点「测试连通性」→ 查看返回状态与耗时 → 保存 → 卡头状态点变绿。

**需求描述**

界面与尺寸：五个字段纵向排列，标签左对齐、宽 120px；API Key 为只读输入框加「显示」「更换」；Base URL 等宽字体；模型为下拉，最小宽 212px；Max Tokens 与并发数为数字输入；底部左侧「测试连通性」与结果位，右侧保存按钮。

数据与排序：默认值为 Base URL `https://api.deepseek.com`、模型 `deepseek-flash`、Max Tokens 4000、并发数 4；Max Tokens 范围 500—8000，并发数范围 1—8；模型选项由后端返回，不写死在前端。

规则与判定：API Key 掩码显示，只露后 4 位；点「显示」明文 3 秒后自动回掩码；「更换」清空当前值并要求重新输入；Key 只存本地配置，不入库、不在界面回显明文；保存按钮在无改动时禁用；测试连通性返回状态码、耗时与返回字数，失败时给具体原因。

异常与边界：Key 无效时返回「API Key 无效或已过期」；超时 10 秒提示「连接超时，检查网络或 Base URL」；Max Tokens 低于 3000 时提示「20 家长报告易被截断」；并发数高于 8 时拒绝保存并提示范围。

**补充说明**

本版本不做多模型并行配置。原因是本期只使用一个模型，多配置会让归档表的「来源」列出现多个值，破坏同一日期一份归档的口径。

#### 特性 3：邮件配置

**用户场景**

换发件邮箱或收件人调整时，需要在这里改完并发一封测试邮件，确认对方能收到。

**输入 / 前置条件**

已开通 SMTP 服务并取得授权码（非登录密码）。

**流程说明**

填写 SMTP 服务器、端口、账号、授权码、收件人 → 点「发送测试邮件」→ 查看结果 → 保存。

**需求描述**

界面与尺寸：SMTP 服务器与端口同一行，端口右侧带 SSL 标识；账号为等宽输入框；授权码为掩码输入加「显示」；收件人为多值 chip（姓名 + 邮箱 + 删除按钮），输入框回车添加；底部左侧「发送测试邮件」与结果位，右侧保存。

数据与排序：收件人按添加顺序排列，不排序；每个收件人显示姓名与邮箱；收件人上限 10 位，超过时提示。

规则与判定：授权码必须提示「不是登录密码」，并给出 QQ 邮箱生成路径；收件人邮箱格式校验，格式错误的地址标红且不参与发送；测试邮件主题固定为「【企业风险监测】测试邮件」，正文一句说明；保存前必须至少有一个格式正确的收件人。

异常与边界：SMTP 认证失败时提示「SMTP 认证失败，QQ 邮箱请使用授权码」；连接超时 10 秒提示检查端口与 SSL；收件人重复时提示「该地址已存在」；测试邮件失败不影响已保存配置。

**补充说明**

本版本不做抄送、密送与分组。原因是本期收件人固定 3 位，分组会增加发信失败面，也会让「3 人」的口径变得不确定。

#### 特性 4：企业名单与批量导入

**用户场景**

新增一家监测企业，或季度调整名单；换企业时需要保留历史，不能把旧记录一起删掉。

**输入 / 前置条件**

维护者持有企业工商登记全称与统一社会信用代码。

**流程说明**

新增：点「新增」→ 填写五个字段 → 保存 → 列表新增一行并默认启用。
停用：点「停用」→ 二次确认 → 状态变停用，历史保留。
导入：点「批量导入」→ 选择文件 → 列映射 → 校验预览 → 确认导入。

**需求描述**

界面与尺寸：名单表 6 列，列宽为企业名称 30%、统一社会信用代码 22%、行业 13%、名单标签 15%、状态 9%、操作 11%；停用行整行置灰；顶部为搜索框、全部/启用/停用分段、批量导入与新增按钮；底部统计「共 25 家　启用 25 家　停用 0 家」。新增弹窗五个字段：企业名称、信用代码（必填）、行业、名单标签、备注。

数据与排序：默认按企业名称升序；唯一键为统一社会信用代码；名单标签枚举为失信公示、守信红名单；新增后默认启用，下次取数纳入。

规则与判定：企业名称必须为工商登记全称，否则源站查询不到；信用代码为 18 位，重复时提示「该信用代码已存在（企业名：XXX）」；停用不删除，历史记录保留，历史统计不重算；批量导入分三步，第二步做列映射（Excel 列到系统字段），第三步给出「可导入 / 重复 / 缺字段」三类计数与逐行预览，只导入可导入行。

异常与边界：导入文件超过 500 行时提示分批；文件格式不支持时提示「仅支持 .xlsx / .xls」；列映射缺少必填字段时「下一步」禁用；导入过程中断时已导入行保留，未导入行不写入，结果页给出行号。

**补充说明**

本版本不做物理删除。原因是删除会让历史风险记录失去企业归属，明细页与趋势的分母随之变化，统计口径会断裂；停用已能表达「不再监测」。
## 4.6 系统设置

### 4.6.1 产品概述

系统设置回答三个运维问题：明天会不会自动跑（定时任务）、现在环境能不能跑（自检）、磁盘还能不能撑（存储与清理）。三块都是低频操作，页头用一句话给出健康结论，默认不展开细节，避免占用汇报视线。

### 4.6.2 产品结构

1. 定时任务：开关、执行时间、下次执行、上次执行结果。
2. 系统自检：六项固定检查，逐项给结果与修复入口。
3. 存储维护：导出诊断包、导出当日资料包、打开数据目录。
4. 保留策略、清理与目录总览：双限制策略、逐项列名的清理预览、折叠的目录健康摘要。

### 4.6.3 状态说明

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 加载中 | 设置数据未返回 | 四块显示骨架，开关禁用 | 无 |
| 正常 | 配置可读，自检无失败项 | 页头一句话给出「全部正常」结论 | 全部 |
| 待处理 | 自检有失败项或存在可清理文件 | 页头写明「N 项待处理」「N 个文件可清理」 | 查看、处理 |
| 保存未生效 | 定时或清理设置有改动 | 对应块底部显示「有未保存的更改」 | 保存、放弃 |
| 执行中 | 自检或清理正在执行 | 按钮显示进行中文案并禁用 | 无 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 相关列如何显示 |
| 通过 | 通过 | 该项检查返回成功 | 绿色状态点 + 结果值 |
| 待处理 | 待处理 | 检查返回失败或未配置 | 琥珀状态点 + 原因 + 建议动作 |
| 超时 | 超时 | 单项检查超过 10 秒 | 灰色状态点 + 「检查超时」 |
| 可清理 | 可清理 | 文件超出保留策略 | 琥珀标签 + 文件名列表 |

### 4.6.4 特性说明

#### 特性 1：定时任务

**用户场景**

演示前一晚需要确认第二天 05:30 会自动跑；临时改时间后，需要看到下次执行时间同步变化。

**输入 / 前置条件**

应用常驻运行，调度器已启动并持久化任务。

**流程说明**

打开开关 → 选择执行时间（时、分双列滚动）→ 保存 → 下次执行时间立即重算 → 到点执行「取数 → 分析 → 发信」。

**需求描述**

界面与尺寸：一行四个字段，分别为执行开关、下次执行（只读等宽）、执行时间（时间选择器，宽约 180px 的两列滚动面板）、上次执行（只读加结果）。卡头显示「定时任务」与状态点「已启用 / 已停用」；底部左侧说明「到点自动执行：取数 → 分析 → 发信，全程约 6 分钟。」，右侧保存按钮。

数据与排序：默认 05:30，每天执行一次；下次执行时间由调度器计算，格式 `YYYY-MM-DD HH:mm`；上次执行显示时间、结果与耗时。

规则与判定：保存后立即重算下次执行时间，不重启应用；关闭开关时下次执行显示「—」；应用重启后任务从数据库恢复，不丢失；同一时刻只允许一个实例运行（`max_instances=1`），错过触发时合并为一次（`coalesce=True`）；关机错过的任务在 7200 秒宽限内补跑。

异常与边界：应用未常驻时自检项「配置完整性」提示定时任务不会执行；补跑超过宽限时记「已错过」并在任务历史留痕；修改时间与保存之间跨过触发点时，以保存后的下次时间为准。

**补充说明**

本版本不使用 Windows 计划任务。原因是调度状态需要与业务库同源，外置计划任务读不到任务锁与上次执行结果，会出现「界面显示已跑、实际没跑」。

#### 特性 2：系统自检

**用户场景**

演示前 5 分钟做一次体检，确认 AI 能通、邮件能发、浏览器能启动、登录态没过期、OCR 模型能加载。

**输入 / 前置条件**

应用已启动。自检只读，不改动任何数据。

**流程说明**

点「开始自检」→ 六项按固定顺序执行 → 逐项显示结果与建议 → 汇总通过数与耗时 → 失败项点右侧文字链跳到对应配置位置。

**需求描述**

界面与尺寸：六行固定顺序，每行结构为状态点、检查项（固定宽 150px）、结果、建议动作（右端文字链）；汇总行显示「6 项　5 通过　1 待处理　·　耗时 2.4 秒」；卡头右端显示「上次自检 时间」。

数据与排序：检查项固定为配置完整性、AI 连通性、邮件连通性、浏览器、登录态、OCR 模型，顺序不随结果变化。通过文案示例：配置项齐全；200 · 1.2s；SMTP 登录成功；Chromium 129.0 已安装，可启动；登录态有效至 23:40；onnxruntime 1.18，模型已加载。

规则与判定：每项失败必须给出可执行建议，例如「SMTP 认证失败，QQ 邮箱请使用授权码」「未安装，请执行 playwright install」「登录已失效，请点企查查登录」「模型加载失败，请重装 onnxruntime」；单项超时 10 秒标「超时」，不阻塞其余项；自检不写入配置、不发送真实邮件、不触发取数。

异常与边界：全部通过时汇总行显示「6 项全部通过」；多项失败时按顺序全部列出，不只显示第一条；自检过程中关闭页面时结果不保存，下次需重跑。

**补充说明**

本版本不做自动修复。原因是修复动作涉及改配置、重装依赖与重新登录，自动执行的风险高于人工确认，且失败原因需要人判断。

#### 特性 3：存储维护

**用户场景**

遇到问题时需要把诊断包发给技术支持；演示结束需要把当日资料打包留档；需要直接打开 data 目录核对文件。

**输入 / 前置条件**

数据目录存在且可读。

**流程说明**

点「导出」生成压缩包 → 浏览器下载 → 或点「打开」直接打开本地目录。

**需求描述**

界面与尺寸：三行，每行为名称、说明、最近生成时间与大小、右侧按钮。诊断包说明为「配置（脱敏）+ 日志 + 快照结构」；当日资料包说明为「明细 xlsx + 分析 md/docx + 发信记录」；数据目录显示路径、总大小与文件数。

数据与排序：行顺序固定为诊断包、当日资料包、数据目录；大小保留 1 位小数并带单位；时间格式 `YYYY-MM-DD HH:mm`。

规则与判定：诊断包必须脱敏 API Key、SMTP 授权码、收件人邮箱（邮箱保留域名）；资料包按数据日期打包，文件名含日期；导出不修改原文件；「打开」调用系统文件管理器，不做页内浏览。

异常与边界：导出失败时提示失败文件与原因，已生成的部分不删除；目录不存在时自动创建并提示；磁盘剩余空间不足 100MB 时提示先清理。

**补充说明**

本版本不做云端上传。原因是部署形态为本地单机，上传需要额外的账号体系与传输加密，本期无使用场景。

#### 特性 4：保留策略、清理与目录总览

**用户场景**

演示前发现磁盘里堆了临时文件；需要先看清要删哪些、多大，再决定是否清理，不能一键删完才发现删错。

**输入 / 前置条件**

存在超出保留策略的文件。

**流程说明**

点「扫描预览」→ 弹窗逐项列出文件名、目录、大小、修改时间 → 勾选 → 点「清理所选」→ 二次确认 → 执行 → 记日志 → 刷新目录总览。

**需求描述**

界面与尺寸：策略表四行，分别为备份文件（30 天 / 20 个）、诊断包（30 天 / 20 个）、日期资料包（90 天 / 100 个）、可清理统计；底部左侧说明「清理前会列出全部文件名」，右侧「扫描预览」。清理弹窗含全选复选框、文件名、所在目录、大小、修改时间五列，底部「已选 N 个 · N MB · 清理后记入日志」与「取消」「清理所选」。

数据与排序：文件按修改时间升序排列，最旧的在前；默认全选；大小合计保留 1 位小数。

规则与判定：保留策略为双限制，超过天数或超过个数都进入可清理；清理为不可逆操作，必须二次确认，确认文案写明「清理后无法恢复，文件将从 data 目录删除并记入日志」；清理只删策略命中的文件，不动当日文件与备份中的最新一份；每次清理写日志，记录文件名、大小、时间。

异常与边界：文件被占用时跳过并记日志，完成后提示「N 个未清理」；无超期文件时弹窗显示「没有可清理的文件」；目录总览默认折叠，折叠态显示「data 5.2 MB　·　1,847 个文件　·　3 个临时文件待清理」，有异常时左侧加 3px 红色竖条，无异常时显示「无异常文件」。

**补充说明**

本版本不做自动清理。原因是清理不可逆，自动执行可能在演示前删掉仍需展示的归档；人工确认一次的成本低于误删的代价。

## 4.7 移动端

### 4.7.1 产品概述

移动端承担的是「随时看结论、随手发日报」，不是 PC 的等比缩小。它以五 tab 承载五个高频场景，配置与系统设置收进「更多」，七屏覆盖从总览到发信的完整链路。移动端与 PC 共用同一套数据与口径，不另算一套数字。

### 4.7.2 产品结构

1. 导航结构与七屏：底部五 tab 加「更多」内的两个二级页，覆盖总览、明细、取数、AI、配置、设置。
2. 总览与明细：2×2 KPI、单序列趋势、优先处理名单、分段与抽屉。
3. 取数与 AI：两源状态卡、最近任务、分析进度与发信入口。
4. 更多、配置与系统设置：数据源比例、只读配置、自检与清理入口、切换电脑版。

### 4.7.4 特性说明

#### 特性 1：导航结构与七屏

**用户场景**

领导在会议间隙打开手机查看今天的高风险企业；操作者在通勤路上确认取数是否成功。

**输入 / 前置条件**

移动端独立页面可访问，PC 顶栏「手机版预览」或直接访问移动端地址进入。

**流程说明**

进入默认总览 → 底部 tab 切换五屏 → 「更多」内进入配置或系统设置（覆盖整屏，返回回到更多）→ 右下 FAB 打开问小启。

**需求描述**

界面与尺寸：设计画布 390×844，宽度 390px 且不超过视口；底部 tab 高 58px 加安全区，白底 94% 透明加模糊，上边框 1px；tab 文字 10.5px、图标 22×22；卡片圆角 14、间距 12px、无阴影；页头演示标识写「演示」。

数据与排序：tab 顺序固定为总览、明细、取数、AI、更多；「更多」内含数据源、关于两组，关于组含配置、系统设置、版本信息；当前 tab 图标与文字为墨色，其余为次级灰。

规则与判定：配置与系统设置不占 tab，从「更多」进入后覆盖整屏，返回回到更多；「切换到电脑版」跳转 PC 页并透传分享码，不得丢失；移动端与 PC 共用同一接口，KPI、等级、三态、单位必须一致。

异常与边界：窄屏小于 360px 时按 100vw 缩放，不出现横向滚动；断网时顶部提示并保留已加载内容；横屏未定义专门布局，按竖屏等比显示（见 8.4 第 9 项）。

**补充说明**

本版本不做响应式收缩。原因是 PC 的 6 列表格在 390 宽下不可读，独立页面才能保证信息密度与点击热区。

#### 特性 2：总览与明细

**用户场景**

开会前 1 分钟需要说出「今天 25 家已取数、20 家有记录、8 家要优先处理」，并能点开某家看记录。

**输入 / 前置条件**

当日存在取数结果。

**流程说明**

进入总览 → 读判断句与 2×2 KPI → 看执行四行与趋势柱 → 点「去生成分析」或切到明细 → 明细分段筛选 → 点企业行打开底部抽屉。

**需求描述**

界面与尺寸：总览页头为「风险总览」加「演示」标签与日期；判断句 13px；KPI 为 2×2 网格，间距 10px，数值 26px；趋势为单序列柱状图（宽 332、高 122），柱顶圆角、柱上标数值、峰值用主色；底部吸底按钮「去生成分析」高 42px。明细分段 5 项横向可滚，栏目 chip 横向滚动，列表每行显示企业名、等级标签、来源摘要与条数；抽屉从底部上滑，最大高 78%，圆角 18。

数据与排序：KPI 顺序为监测企业、风险记录、重点风险、应分析，单位分别为家、条、条、家；分段固定为全部 20、高 8、中 5、低 7、红名单 5；明细列表默认按综合等级降序、同级按条数降序。

规则与判定：判断句按固定模板生成「今日 25 家已取数，20 家发现风险记录，8 家需优先处理。」；趋势 7 天为 7 根柱，30 天为 30 根，0 条的日子画 2px 小墩；抽屉内容与 PC 明细弹窗口径一致，按来源分组；点击遮罩或下滑关闭抽屉。

异常与边界：无数据时判断句改为「今日尚未取数」，KPI 显示破折号；企业名过长时两行截断；抽屉内记录超过 30 条时内滚，不一次渲染全部。

**补充说明**

本版本不做 PC 全量表格镜像。原因是手机屏幕无法承载 6 列加长文本，逐条核对仍在 PC 完成，移动端只保证「看出问题、找到企业」。

#### 特性 3：取数与 AI

**用户场景**

通勤路上确认两源取数是否成功；到公司前先把分析跑起来，或直接发日报。

**输入 / 前置条件**

当日存在任务记录与配置。

**流程说明**

切到取数 → 查看两张源卡与最近任务 → 点「重新取数」走二次确认 → 切到 AI → 点「生成分析」或「发送邮件」→ 查看最近分析与最近 3 封邮件。

**需求描述**

界面与尺寸：取数页两张源卡，每卡含标题、状态标签、最后执行、耗时、入库与两个按钮；最近任务列表 5 行，每行时间、步骤、状态。AI 页进度卡含状态与 2×2 四指标，两个按钮并排；最近分析卡显示「6 页 · 20 家」并可点开预览；邮件记录显示最近 3 封，每行时间、主题、状态。

数据与排序：四指标口径与 PC 一致（本期企业 25、应分析 20、已完成、失败）；最近任务按时间倒序；最近分析按生成时间倒序；邮件记录按发送时间倒序。

规则与判定：移动端「生成分析」「发送邮件」的规则与 PC 完全一致，包括无分析时先分析再发、演示环境二次确认；「重新取数」为覆盖性操作，必须二次确认；移动端不提供「运行全流程」。

异常与边界：分析进行中切走再回来，进度按 3 秒轮询恢复；发信失败时记录状态为「失败」并显示原因；未配置时按钮禁用并提示去 PC 配置。

**补充说明**

本版本不做「运行全流程」。原因是全流程耗时数分钟，移动端误触成本高，且中途切后台会让人误以为任务中断。

#### 特性 4：更多、配置与系统设置

**用户场景**

需要确认数据源比例与版本；临时查看 AI 与邮件是否已配置；演示前跑一次自检。

**输入 / 前置条件**

已进入移动端。

**流程说明**

点「更多」→ 查看数据源与关于 → 进入配置（四张只读卡）或系统设置（三张卡）→ 返回更多 → 点「切换到电脑版」。

**需求描述**

界面与尺寸：更多页为分组列表，数据源组两行（信用中国 25/25、企查查 23/25），关于组三行（配置、系统设置、版本信息），底部为「切换到电脑版」文字链（虚线下划线）。配置页四张卡为字段行式，标签左、值右，只读项右侧灰字；系统设置三张卡为定时任务、系统自检、存储。

数据与排序：配置卡顺序为数据来源、AI 配置、邮件配置、企业名单；系统设置卡顺序为定时任务、系统自检、存储；版本信息显示「v1.0 · 演示快照」。

规则与判定：移动端配置为只读，不提供编辑与批量导入；「开始自检」与 PC 同一套六项逻辑；清理与导出在移动端只给演示反馈，不执行真实删除；「切换到电脑版」保留分享码。

异常与边界：未配置时值显示「未配置」并提示到 PC 完成；自检失败项在移动端只显示结果与建议，不提供修复入口。

**补充说明**

本版本不做移动端配置编辑。原因是字段多、校验复杂，误改会直接影响次日自动跑批，配置统一在 PC 完成更可控。

## 4.8 风险助手「问小启」

### 4.8.1 产品概述

问小启用自然语言回答「今天哪几家最严重」「企查查为什么少了 2 家」这类问题，降低找数成本。它的定位是只读查询助手，不是第二个操作入口：能查、能解释、能导航，不能发信、不能取数、不能改配置。所有回答只基于当日快照，越界一律说「没有」。

### 4.8.2 产品结构

1. 入口与面板：PC 侧栏入口与浮动面板，移动端 FAB 与全屏面板。
2. 只读边界与回答规范：数据边界、等级口径、可用能力、禁止事项与回答格式。
3. 降级、设置与对话管理：无 Key 的本地兜底、错误提示、模型设置与清空对话。

### 4.8.3 状态说明

**页面状态**

| 状态 | 触发条件 | 呈现 | 可用操作 |
| 关闭 | 默认 | 仅显示入口，不自动展开 | 打开 |
| 空闲 | 已打开，无对话 | 欢迎语与 3 条示例问题 | 输入、设置 |
| 思考中 | 已发送，等待返回 | 机器人 think 动效，输入框禁用 | 停止 |
| 已回答 | 返回成功 | 消息区追加回答，末行显示依据 | 继续追问、复制 |
| 降级 | 无 Key 或断网 | 回答末尾标「本地规则作答」 | 重试、设置 |
| 失败 | Key 无效、限流、超时 | 具体错误加处理入口，保留输入 | 重试、改设置 |

**数据状态**

| 状态 | 显示文案 | 判定依据 | 回答如何呈现 |
| 快照内 | 正常回答 | 问题命中 system_data | 结论 + 依据 + 依据行 |
| 快照外 | 当前快照里没有这条信息 | 企业、日期、数字不在快照内 | 只说明没有，不推测 |
| 越权 | 只读助手，不能执行该操作 | 请求发信、取数、改配置 | 说明边界并给页面导航指引 |
| 无 Key | 本地规则作答 | 未配置或 Key 无效 | 只答概况、名单、失败原因、邮件状态 |

### 4.8.4 特性说明

#### 特性 1：入口与面板

**用户场景**

领导突然问「今天高风险是哪几家」，操作者不想切页面找，直接在助手里问；手机上同理。

**输入 / 前置条件**

系统已加载当日快照。PC 与移动端共用同一套助手逻辑。

**流程说明**

点侧栏「问小启」或移动端 FAB → 面板打开 → 输入问题 → 回车发送 → 等待回答 → 继续追问或关闭。

**需求描述**

界面与尺寸：PC 面板 400×640，圆角 14，白底，1px 边框，阴影，距右下 20px；侧栏入口为整块按钮（头像 28px、主文案 12.5px、副文案 11px、未读点）。移动端为胶囊 FAB（高 44）加全屏面板（距边 8px）。面板结构为头部（头像、标题「风险助手」、副标题「演示快照 · 只读」、设置、关闭）、消息区（`role="log"`）、输入区（单行自适应 textarea、发送按钮、说明「只读助手 · 不执行任何操作 · Enter 发送 / Shift+Enter 换行」）。

数据与排序：消息按时间正序追加，最新一条在底部并自动滚入视口；历史最多保留 30 条、取最近 6 轮；开场给 3 条示例问题，按当前快照生成。

规则与判定：不自动展开、不自动弹键盘；Enter 发送、Shift+Enter 换行；关闭后保留对话，重开恢复；切换页面不关闭面板；PC 面板与移动面板共用同一份对话存储。

异常与边界：超长问题超过 500 字时截断并提示；发送中禁用发送按钮，可点「停止」；断网时保留已输入内容并提示。

**补充说明**

本版本不做语音输入。原因是语音需要麦克风权限与转写链路，演示场景下键盘输入已够用，增加权限会带来额外解释成本。

#### 特性 2：只读边界与回答规范

**用户场景**

有人问「这家会不会被处罚」「帮我直接发给领导」，助手必须明确拒绝，并告诉对方去哪里操作，而不是编一个答案。

**输入 / 前置条件**

问题已发送，快照数据已注入。

**流程说明**

收到问题 → 判断是否在快照与能力范围内 → 命中则按「结论 + 依据 + 依据行」生成 → 未命中则说明没有 → 越权则说明边界并给导航指引。

**需求描述**

界面与尺寸：回答正文 12.5px、行高 1.7；结论 1—2 句置顶；依据分点，每点含企业全称、类型、日期、来源；末行固定「依据：{日期} 快照 · 演示数据」，字号 11px、次级灰。

数据与排序：只能使用注入的当日快照数据；列举企业最多 5 项，超出写「另 N 家」；回答总长不超过 260 字。

规则与判定：等级由系统按 11 类栏目映射计算，助手只引用，不重新判定、不加总、不比较、不建议升降级；允许回答整体统计、单企业记录说明、栏目口径、任务与失败原因、分析与邮件状态、配置自检说明、页面导航；禁止发信、取数、改配置、删归档等写操作；禁止处罚预测与法律意见；禁止输出 API Key、密码、授权码，只答「已配置 / 未配置」。

异常与边界：问到快照中没有的企业或日期，回答「当前快照里没有这条信息」，不推测、不补全、不举例；问到需要写操作的需求，回答「只读助手，不能执行该操作」并给出对应页面；问题含糊时先按最接近的口径回答，并在末行注明理解口径。

**补充说明**

本版本不做多轮任务执行。原因是写操作会绕过二次确认与操作留痕，一旦助手能发信，责任边界与失败处理都无法界定。

#### 特性 3：降级、设置与对话管理

**用户场景**

演示现场没有网络，或 Key 失效，助手仍要能回答最基本的几个问题，不能整个面板报错。

**输入 / 前置条件**

助手已打开。模型服务可能不可用。

**流程说明**

发送问题 → 优先调用模型 → 无 Key、断网或调用失败时切本地规则 → 返回结果并标注作答方式 → 点设置修改 Key 或清空对话。

**需求描述**

界面与尺寸：设置弹层含接口地址（只读）、模型（只读）、API Key（密码输入框）、对话条数与「清空对话记录」。Key 说明固定为「仅保存在本机浏览器，不写入文件、不发送到本系统之外的任何地方」。

数据与排序：接口地址固定 `https://api.deepseek.com`，模型固定 `deepseek-flash`，只读不可改；对话条数显示「共 N 条」。

规则与判定：无 Key 或断网时走本地规则兜底，能回答整体概况、高风险名单、取数失败原因、邮件状态，末尾标注「本地规则作答」；Key 无效时提示「API Key 无效或被拒绝，点右上角设置重新填写」并给重试；限流时提示稍后重试并保留输入；超时 30 秒；用户中断时显示「已停止生成。」并给重试；对话不写入服务端，清空后不可恢复。

异常与边界：本地兜底无法回答的问题，明确说「本地规则无法回答，请配置 API Key 后重试」；清空对话需二次确认；设置保存后立即生效，不需要刷新页面。

**补充说明**

本版本不把对话写入服务端。原因是对话可能包含企业名与风险描述，本地留存即可满足追溯，写入服务端会扩大数据边界。
# 五、其它产品需求

## 5.1 性能需求

以下指标的前提均为：25 家监测企业、22 条风险记录、本地 MySQL 单实例、1440×900 分辨率。数据量级变化时需重新评估。

| 指标 | 目标与说明 |
| 总览首屏 | 可读 ≤2 秒：从进入页面到四卡、执行链、待处理名单可见，不含图片资源 |
| 页签切换 | ≤0.5 秒：六页之间切换，不整页刷新 |
| 筛选搜索 | ≤0.3 秒：输入停止 300 毫秒后触发，22 条记录量级 |
| 明细弹窗 | ≤0.3 秒：含按来源分组渲染 |
| 分布图 | 翻页 0.42 秒：位移动画时长；停留 10 / 6 / 6 秒 |
| 快照回放 | 2—4 分钟：单家 2—6 秒，模拟真实取数节奏 |
| AI 分析 | ≤30 秒：20 家，并发 4、单家接口返回 ≤1.5 秒时 |
| 邮件发送 | ≤30 秒：3 位收件人、2 个附件 |
| 系统自检 | ≤30 秒：六项，单项超时 10 秒 |
| 助手响应 | ≤5 秒：首个响应；整段超时 30 秒 |

AI 分析的三个数字对应三种环境，不矛盾：≤30 秒是并发 4、单家返回 ≤1.5 秒时的目标值；单家接近 60 秒超时上限时，20 家按并发 4 约需 5—6 分钟，这是最坏情况；演示环境把分析过程压缩到约 6 秒，页面提示条仍按真实环境的估算写。

## 5.2 监控需求

监控分记录、统计、告警三层，本期不做外部告警通道。

| 层 | 内容 | 位置与保留 |
| 记录 | 任务执行记录（数据日期、步骤、状态、耗时、尝试次数、错误摘要）、邮件发送记录、分析归档索引、运行日志 | 前三类存 MySQL，随库保留；运行日志存 `data/task_logs/`，按 4.6 保留策略清理 |
| 统计 | 今日执行状态句（完成步数、失败数、入库条数）、任务历史双筛选、四卡环比 | 取数页与总览页实时计算，不落统计表 |
| 告警 | 页内错误条（四要素）、系统托盘通知 | 只在本地可见，不做短信、电话、企业微信推送 |

告警触发的条件固定为：任一执行步骤失败、分析失败、邮件发送失败、磁盘可清理文件超过 20 个。托盘通知点击后跳转到对应页面，不重复弹窗。

| 项 | 要求 |

## 5.4 安全需求

本系统不设登录与权限体系，数据边界与凭据保护由以下规则承担。

| 项 | 要求 |
| 访问控制 | 本期不设登录，风险由物理环境承担（本地单机、值班账号）。此为本期已知并接受的风险，见第六章 |
| 凭据保护 | API Key 与 SMTP 授权码掩码显示，只存本地配置；助手 Key 只存本机浏览器；任何页面不回显明文 |
| 导出脱敏 | 诊断包必须脱敏 API Key、SMTP 授权码、收件人邮箱（保留域名） |
| 演示标识 | 页面四处标识常驻且不可关闭；导出文件页脚与邮件主题带演示声明 |
| 数据边界 | 只处理企业公开公示信息，不采集个人信息；对外材料中的企业名称、金额、案号按法务要求脱敏或替换 |
| 助手边界 | 只读，不执行发信、取数、改配置、删归档；不输出密钥；不回答处罚预测与法律意见 |

# 六、风险分析

风险按「可能性 × 严重性」分级，只列业务与数据层面，技术实现风险见《开发实施说明书》。

| 风险 | 可能性 | 严重性 | 应对策略 | 可应对性 |
| 快照数据固定不变，多次演示数字完全相同，被误认为实时系统 | 高 | 中 | 页面四处演示标识常驻；页脚写明「数据截至 2026-10-21 05:34」；演示卡写明「非实时抓取」；汇报时先说明数据口径 | 部分可应对，快照性质不可消除 |
| 未采集或无权限被读成「无风险」，导致结论偏乐观 | 中 | 高 | 三态视觉可区分；采集失败时等级列显示破折号；明细弹窗按来源分组并标「无权限」；验收项单独检查三态 | 完全可应对 |
| 跨源去重键在机关缺失时用描述前 20 字兜底，可能漏去重，记录总数虚高 | 中 | 高 | 去重键入库为唯一指纹；页面显示「去重 3 条」与「去重后 22 条」；明细弹窗标「双源印证」；发现异常时按指纹复查 | 部分可应对，兜底规则存在漏判 |
| AI 输出越界定级或编造证据，结论不可信 | 中 | 高 | 输出契约禁止等级字段；每条结论必须带 evidence 指向真实记录；代码层校验，不通过重试 1 次后走规则兜底；界面注明「AI 只解读，等级由规则计算」 | 完全可应对，有规则兜底 |
| PC 与移动端同一指标口径漂移，汇报数字对不上 | 中 | 中 | 两端共用同一接口；单位对照表写入文案规范；验收项逐条比对两端 KPI、等级与三态 | 部分可应对，需每次发版回归 |
| 单机无鉴权，设备被他人使用时可发信或改配置 | 低 | 中 | 物理环境管控；密钥掩码；诊断包脱敏；本期不上线对外，仅本地演示 | 不可应对，接受该风险 |

## 8.2 术语与指标口径

单位绑定为强制规则：企业用家，风险记录用条，模块与字段用个，需求与指标用项，栏目类型用类。

| 术语 | 解释 |
| 监测企业 | 配置且启用的企业，唯一键为统一社会信用代码；单位为家 |
| 风险记录 | 一条公示记录，去重后进入统计；单位为条 |
| 应分析 | 当日有风险记录的企业数，单位为家，禁止写成「应分析 N 条」 |
| 重点风险 | 等级为「高」的风险记录数，单位为条 |
| 未发现 | 采集成功，未检索到记录；等级显示「无」 |
| 未采集 | 采集失败，可重试；等级列显示破折号 |
| 无权限 | 账号无该栏目权限；不计入失败，等级列显示破折号 |
| 双源印证 | 同一条风险同时被信用中国与企查查收录，去重后保留一条并标「双源」 |
| 红名单 | A 级纳税人、守合同重信用等正面资质，不是风险，不写入风险记录表 |
| 栏目归一化 | 把两源的原始栏目名映射为 11 类标准类型，映射关系见 8.3 |
| 综合风险 | 一家企业全部记录中的最高等级，取高不取平均 |
| 新增 | 该记录在上一可用数据日期不存在；首次采集时全部标为非新增 |
| 演示快照 | 2026-10-21 05:32—05:37 冻结的静态数据，非实时抓取 |
| 归档 | AI 分析结果落盘后的索引记录，含 MD 与 DOCX 两种文件 |
| 问小启 | 风险助手的名称，只读查询助手，不执行任何写操作 |
| 经营风险 | 企查查的一个栏目，当前账号无该栏目权限，取数时按「无权限」呈现 |
| 今日需处理 | 总览页的高风险企业名单区块，最多 3 行，点击进入企业明细弹窗 |
